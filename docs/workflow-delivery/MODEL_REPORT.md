## 条件与判定

固定四个小型 Python 仓库任务：区间合并缺陷、标签解析测试、统计逻辑重构、分页功能。初始文件、目标、允许修改范围、独立行为断言及两项指定 mutant 在首次请求前冻结。独立评判器不放入模型工作区；检查真实文件、公开回归、新测试执行、固定行为与越界改动，不读取模型总结作为结论。宿主生成的蓝图仅在字节完全匹配时从修改范围中排除；首次运行另以持久 run 根图逐一核对，全部匹配，额外文件单列。

同一 `deepseek/deepseek-v4.1-flash`、同一初态和权限；首轮每个实现阶段 8 轮，框架另有 1 轮无工具收尾，输出上限 1024 token。监督模式在实现后、确定性验收前加入真实 OversightCheckpoint，最多 2 轮/512 输出 token。每单元最多 12 请求、禁止自动重试。四任务轮换模式顺序。模板由工程阶段预先准备，因此测量的是固定模板执行，不是自动规划能力；准备时间未单独计时，不能声称为零。

完整交付同时要求运行正常结束、独立产物验收通过、范围正确、保存蓝图与冻结 run 一致。确定性 Passed 与人工接受仍是两件事。每单元墙钟时间包括启动隔离服务和独立评判；不包含前期工程/编译时间。批准测试命令及监督 gate 的操作由夹具按冻结规则执行，计数见 JSON，不冒称真实人工时间。监督否定 gate 可以显式继续，但不改写监督结论或自动重试。

费用按 [CommandCode 官方 Flash 价格](https://commandcode.ai/models/deepseek-v4-1-flash) 于 2026-10-24 核对的峰值输入 US$0.30/M、输出 US$1.20/M 保守记账，不使用缓存折扣，也不冒充账户账单。179 个请求均有 usage：输入 1,287,276、输出 61,441，其中供应方报告缓存输入 1,031,808、reasoning 18,522；缓存没有人为固定冷/热条件，不能据此作模式节省百分比结论。所有规划/执行/监督/失败补验共用一本 ledger。
