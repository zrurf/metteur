# 日常使用与恢复

## 从目标开始

在 Chat 或蓝图编辑器选择 **Start from template**，选择 Fix a bug、Add tests、Refactor safely 或 Add a small feature。填写目标、文件范围和验收要求；检查命令、证据文件、基线、模型及迭代上限在折叠选项内。路径指向工作区内的具体普通文件，不支持通配符、目录、符号链接或 `.git`/`.metteur`。预检只读，缺文件会提示；它不证明外部工具已安装或测试必然通过。

**Preview plan** 展示阶段及要求；**Create blueprint** 在工作区根目录创建独立 `.blueprint` 文件并同步宿主镜像，不执行。相同名字已有文件时保留输入并要求改名，不覆盖原件。文件已创建但镜像失败时按提示重试同步；未知写入先读取同路径并比较完全相同的正文，不换实例 ID 再造一份。

从已存在的 Chat 会话进入时，**Prepare run in original Chat** 把明确提案加入原草稿，保留已有文字。用户再显式 Send，通过原 RequestBlueprintRun 确认具体版本、交接及完成策略。主聊天保留原会话，监督仍从 Execution 独立入口进入。尚未产生会话的新聊天不伪造来源，保存后按独立蓝图处理。

独立蓝图可从普通编辑器或 Execution 的 **Select blueprint** 打开。Run 前会显示要求和已保存版本，**Commands & exact dependencies** 展开命令与精确依赖。取消保留选择且不执行；确认后文件、Prompt、节点/工具/函数/插件目录、模型或沙箱配置变化都会阻断旧确认，需要重新准备。确认不代替后续命令权限审批。

## 编辑与验收

蓝图是普通可编辑阶段图。保存/恢复保留 Start 上的验收契约；模板目录更新不修改既有实例。参数名来自具体工具，画布不把 `command` 改成显示标签。修改检查命令、预期退出或绑定连线时，必须同步明确修改验收契约；否则 Save/Run 会拒绝，不能用改节点绕过原验收。原生 `.blueprint` 保留全部元数据；DSL 不承载这些身份，导出此类实例会明确拒绝，使用原生文件复制。

结果页选择 **Review delivery**。执行状态、确定性检查和人工接受分别显示。基线折叠呈现：修 bug 的基线必须匹配指定非零退出，最终检查必须为零；命令启动失败、超时或缺证据不算重现或通过。

- **Passed / Failed**：冻结 run 中真实当前检查与输出的结论。
- **Missing / Skipped**：所需记录/文件缺失或未执行，不能接受为通过。
- **Stale**：检查后内容变化或绑定失效；历史记录保留，当前接受失效。
- **Needs review**：需要人判断的要求，不是模型自己宣告通过。

**View evidence** 查看命令输出和文件，文件入口沿用普通编辑器的未保存保护。Accept/Request changes 和备注绑定主体、run、要求及当前证据摘要；不会授予执行权、清预算或重跑。只覆盖声明的文件与检查，不能证明全部 shell、网络或外部副作用。文件每项上限 4 MiB，总捕获上限 32 MiB；检查输出展示有截断与脱敏，超限/不可读均如实显示。

每 run 最多 16 条要求、64 次人工修订；备注最多 2048 字节，单资源 16 KiB，审阅资源最多 128 runs。达到上限显式拒绝，历史回执不被删除。模型和插件没有人工验收入口。

## 失败、未知和恢复

计划表单、人工备注和未决请求通过宿主 Recovery ACK 保存；浏览器本地标识不是正文权威。刷新后可从 **Recovery copies** 选择计划副本；恢复仅复制输入，重新预检当前资源。草稿 ACK 失败时保留输入并禁止提交审阅。

审阅断连显示 **Check original receipt**。重新打开该 run 会扫描已备份的未决请求；先查询原请求 ID，只有宿主明确无回执时才以原身份重发，不能另造一个决定。内容不匹配、跨 run/主体/工作区、CAS 冲突或无法完整读回都会显式失败。已经成功的回执不因后续文件变化而消失，但旧决定不再表示当前证据被接受。

**Prepare follow-up in Chat** 只把验证过的结果引用与未满足要求加入原聊天草稿；独立运行可放入当前聊天草稿。来源无法核实时阻止转交。必须显式 Send 才会提出下一步；原任务历史、预算与前台占用守卫沿用已有机制。Stop、未知副作用、挂起恢复遵守现有控制流程，不隐式重跑。

旧图没有验收契约时显示无逐项要求，不补造历史通过。旧数据库保持兼容；本阶段新增命名空间和可选 checkpoint 字段不改变既有任务账本。回退前必须停止对应服务，再恢复成套的冷备数据/工作区/配置，勿混用新旧同时打开的数据库。旧 DW 的真实 IME、S3 和长期观察接受边界继续有效，本阶段不把技术检查写成人工实测。
