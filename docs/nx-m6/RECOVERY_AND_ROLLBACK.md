# 恢复与回退指南

## 恢复源码
1. 保留现有目录和改动，不在原目录 reset、clean 或解压覆盖。
2. 在新目录克隆交付包内的 Git bundle；核对报告 HEAD、git status 和 SHA256SUMS。
3. source/ 是同一提交的完整可读源码。依赖目录、编译缓存和凭证不包含在交付包中。
4. 记录当前运行程序、工作区路径和数据目录，再决定是否切换程序。构建在新目录进行。

## 数据保护
- 关闭正在写入的实例，保留整个工作区、daemon 数据目录、审计日志、文件操作 journal、Prompt 源文件及个人资源。
- 使用应用的数据库 checkpoint 或停止写入后的完整目录副本；不要随手复制正在写入的 RocksDB 若干文件并声称是有效备份。
- 资源层首次迁移前创建 nx-before-v1 checkpoint；已有版本和备份不覆盖。定向测试验证了旧会话保留、CAS/重复请求、重启、未知 schema 拒绝写入和备份可读。
- 源码回退不回滚文件和外部副作用。发生超时/取消后检查 journal 与实际文件；网络请求结果未知时不能因 lease 到期重放。

## 功能收窄
Pause 或 Stop 对应续跑任务；取消相关 schedule；完成已有运行后再停用 Addon。禁用不会删除报告和历史记录。未知/未结清的运行进入 Needs attention，不自动重放。

## 降级边界
不能保证更旧的可执行程序识别新数据。应在隔离副本上验证；未知 schema 拒绝写入时停止操作，不篡改 schema 标记“让它通过”。保留原数据库供新版本读取，必要时仅查阅导出的记录。此次没有在用户原始数据库上进行破坏性降级。

## 已验证与未验证
已验证：真实源码 bundle 克隆、哈希；资源迁移备份/重启/拒绝未知 schema；损坏会话恢复前阻断副作用；Prompt 快照保留；重复事件/恢复边界。
未验证：原生 Windows 运行、完整旧二进制读写兼容矩阵、长时间真实供应商任务、1k 节点/10k 日志性能基线。它们不能从 Linux 的小型定向验证推出。
