## 第一组：真实输入法，约3分钟

1. 打开Chat，用你日常Windows中文输入法输入“输入法验收”等中文，**按一次Enter确认候选**。汉字应留在输入框，历史中没有新用户消息。用Shift+Enter换行，也不发送。
2. 候选确认结束后，**有意按住Enter约1秒发送这一稿**。历史应只新增一条用户消息，没有因长按重复提交。这里连接本地脚本provider，不是付费模型。
3. 在Execution标题下拉选择`input-guard.blueprint`，Run。这个蓝图由12个10秒等待节点组成，总计2分钟，无文件/命令/模型副作用。返回主Chat，用真实IME输入“占用不发送”，确认候选；尝试Ctrl+Enter、Tab和发送菜单入口。正文应保留，历史不增加，禁用规则不能绕过。
4. 返回Execution，Stop这个等待蓝图，等状态停止。不用等它自然完成；Stop后到下个节点边界收尾，最多约10秒。这里只清理人工样本，不重做Stop验收。

## 第二组：真实睡眠/唤醒，约3–5分钟

仅在后续实际安排补验并确认运行入口后继续，本轮无需现在操作。

1. 主Chat保留未发送文字；打开`sleep-draft.txt`，追加“睡眠前未保存：中文验收”，**不保存文件**。两处均等到Backed Up on Host。
2. 在Execution选择`sleep-wake.blueprint`并Run（只有等待90秒）。在约30秒内，从Windows开始菜单→电源→**睡眠**，实际睡眠约2分钟后唤醒。不是锁屏、关闭浏览器或休眠。系统已只读核实支持S3。
3. 唤醒后等待连接/计时收尾，不重新Run或Send。原run应对账并结束，不能另起重复run、自动发送主Chat草稿或丢失文字。若仍运行/报错，记录现状；不要为凑通过重试。
4. 刷新一次页面，分别从Chat和文本编辑器的Recovery Copies预览并Use This Copy。确认未发送聊天和未保存文件文字可取回，且没有自动发送或覆盖保存到磁盘。
