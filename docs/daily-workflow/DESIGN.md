## 3. 主聊天、监督和准入

- 主聊天视图绑定 workspace/session，监督绑定 workspace/run/conversation。打开深链按指定对象解析；无权限、来源删除或历史数据缺失时显示 unavailable，不回退到“最新对象”。
- 蓝图 Starting、Running、Paused、等待审批及恢复中仍占用／可能占用准入时，所有会话的普通 Send、Queue、Steer、Retry 和快捷键均不得绕过。展示具体原因和 Open supervision；保留 Stop 的明确 run 目标。
- 断线时不把 active=false 当空闲；先查询持久状态。终态持久化、所有权／副作用对账及准入释放完成后恢复普通发送；模型总结是否完成不决定槽位归属。
- “任务 Waiting”不自动等于蓝图占用。若前台槽位已释放，普通聊天按既有准入规则可用；有写能力后台任务还受 effect lease 限制。
- 客户端禁用负责交互，宿主准入负责所有客户端。独立监督不启动第二个普通 ReAct，不转发主聊天未提交的草稿。
- 普通 ReAct 的既有排队／插入行为保留，固定 turn 身份。队列不跨结束回合自动迁移；失效返回草稿或明确未接收状态。
- 允许编辑缓冲区；正式文件保存仍通过现有路径校验、冲突检查和适用写入保护。蓝图保存不代表立即热应用。
- 运行卡与 Execution 共享展示模型和控件；直接暂停／停止不依赖模型。没有客服模型仍能看状态、提案历史和直接控制。
- 自动续聊按已有策略在原 session 创建新 turn；未发送草稿不改变 session revision，也不会被自动带入模型。人工停止不自动重跑。
- 编辑器直接运行蓝图沿用既有保存、校验、准入和审批。没有 LaunchIntent／源会话时显示独立运行，不伪造 parent task/session、不自动续聊；用户可明确将结果加入选定会话草稿。Chat 发起的交接继续使用完整 launch 契约。

## 4. 恢复记录

### 4.1 身份与最小字段

下列名称为语义字段，不要求照抄成最终 proto 名称：

| 对象 | 必需内容 |
|---|---|
| DraftKey | 认证主体、宿主解析的 workspace／个人 scope、entity kind、session/new-chat ID 或资源身份、独立 draft ID |
| DraftRecord | schema、记录 revision、客户端 edit sequence、原始正文／画布数据、基线内容身份、附件／Prompt 的有序引用、更新时间、状态 |
| RecoveryMetadata | client/window 标识、未决 submission ID、已提交 edit sequence、原 session/run 绑定、保存／丢弃 tombstone |
| ViewState | 选中会话、文档标签和当前标签、游标／选区／滚动或画布视口；它不能成为执行权限依据 |

宿主决定 owner/scope 和规范路径；不相信客户端自报 owner，不在前端统一 lower-case Windows/Linux 路径。不同窗口使用独立 draft ID；复制标签页如果继承标识，重新取得独立窗口身份。重开可列出同一用户的恢复副本，不用最后写入覆盖另一份。

普通文档正文、蓝图文本中的无效 JSON、Prompt 无效 front matter 都是可恢复输入。正式保存才校验格式。画布保存可编辑模型和视图状态，不需要跨重启恢复完整 undo 栈。

### 4.2 备份、保存与丢弃

1. 编辑立即更新内存和 edit sequence；建议起始 debounce 750ms、持续编辑最长 5s 发起一次备份。同一草稿至多一个在途写，合并后续编辑；这些是实施初值，DW-00 测量后可调整。
2. 备份携带 expected record revision 和 request identity；宿主完成原子 durable 写后才确认该 edit sequence。更新中的输入不会因旧回执被标为已备份。
3. 冲突返回结构化原因及当前 revision；本地副本继续保留。传输失败／容量不足明确显示未备份，不阻止用户继续编辑。
4. 正式保存成功只清理与已保存内容对应的草稿版本；保存期间的新输入继续备份。保存文件与清理副本之间崩溃，恢复时用内容身份辨认冗余副本，不覆盖磁盘。
5. 明确丢弃使用版本条件与 tombstone，阻止晚到写重新复活被丢弃的内容。页面关闭、换 session、模型失败都不是丢弃。
6. 宿主确认的 rename 迁移关联，保留旧身份的转移记录；外部 rename／文件缺失只报告原引用失效，不凭名称或相同内容猜目标。删除后恢复文件沿用 create-only。
7. 删除 session 前说明关联草稿处理；默认保留可手工取回的孤立草稿，不自动重建 session。run 结束后的监督草稿保留只读，可显式复制正文，不自动提交到下一 run。
8. 恢复先比较磁盘／资源最新状态，再将选定恢复副本装入编辑器。草稿内容不是磁盘内容、模型输入或批准动作。
9. 离线期间不写持久浏览器缓存，不承诺崩溃恢复；提示未备份并保留内存输入。重连先对账，在内容未变化时可续传同一备份请求，冲突则提示。

“已备份”保证不包括宿主磁盘丢失或手工恢复整套旧数据库。业务 rewind 不得影响恢复记录；整库灾备回滚需先导出最新恢复记录并说明影响。

### 4.3 存放、容量和访问

复用现有 RocksDB／用户存储、安全路径及 durable/CAS 原语；项目与个人 scope 分离。采用新的有界草稿 namespace 或等价专用存储，不把逐键备份直接送入 append-only ResourceStore 历史，也不加入文件 Version Flow／执行 checkpoint。

保留最新确认稿和必要的在途对账／删除凭据；丢弃旧正文需要能证明不是唯一未解决副本。未解决草稿不得按年龄自动淘汰。DW-00 核对实际可编辑大小与 RPC 上限，冻结单记录、单用户 scope 总量、分页／批次上限及超限呈现；未冻结上限不交付存储实现。超大内容明确不受备份保护，不能截断后返回成功。

备份写不能引发全工作区聊天／任务／文件重载；使用有类别的通知或等价订阅过滤，保持必要共享刷新。错误日志只记录身份摘要与错误码，不记录正文、凭据或个人 Prompt。

读取、备份、恢复、复制、清理均核验当前用户权限。自动恢复只恢复输入和偏好；模型、工具、Prompt 访问和 permission mode 按当前有效配置核验，不恢复旧 AllowOnce、full 权限或已撤销策略。

## 5. 投递回执与兼容

前端状态为 Draft → Submitting → Accepted，或 Rejected / Unknown；Accepted 后的 running、failed、interrupted、completed 属于执行结果。不要把模型失败退回成“未发送”。

- 提交快照含 workspace/session 或 stable new-chat ID、期望会话 revision、目标 turn（适用时）、正文、有序附件／Prompt 身份、当前选择参数和逻辑 request ID。
- 接收点位于权限／资源校验和准入之后、可能产生执行效果之前。接收记录、分配的 session/turn、输入身份及会话 revision 变化应原子提交或具备可证明等价恢复协议。普通消息不能仅在最终回答保存时才拥有接收证据。
- Accepted 表示输入已持久接收，不承诺浏览器断开后继续执行。普通聊天保持原断流保护；只有已授权 detached task 按原规则继续。
- 回执丢失时按同一 ID 查询；未决 submission ID 要与恢复草稿关联持久化，避免重开只剩文字然后重复发送。明确未接收后才允许恢复为新编辑／新提交。
- 同一 ID 同内容返回原 session/turn 与状态；同一 ID 异内容拒绝。相同正文的主动再次发送使用新 ID，不按文本去重。
- 接收后启动前崩溃：只能在可证明没有开始时恢复同一逻辑 turn；未知效果进入明确人工处置，绝不能新建一次执行。
- 拒绝的请求不新增用户消息、不推进 session revision。新消息“已接收”才使旧 continuation 失效；单纯编辑草稿不产生此效果。
- 已接收的排队／插入消息有原 turn 和 disposition；回合结束后未消费显示未处理，不能自动发给下个 turn。
- 新客户端面对不支持回执／恢复的旧服务明确显示能力不足；不静默声称受保护。协议采用兼容增量并更新 proto 生成物、Web gateway/mock、CLI 和涉及的调用方。旧请求可保留原语义，但不宣称有新幂等保证；所有客户端必须经过相同宿主准入。
- 查询／清理有权限、分页和上限。投递去重记录的保留与归档由 DW-00 冻结；清理后保留足以拒绝旧 ID 的轻量凭据或显式过期规则，不能忘记后把旧请求当新请求。
- 控制和审批复用已有可信执行服务与内容绑定，补失败／未知对账。不要为了界面回执建立第二个执行队列或宽泛 control RPC。

IME composition 期间 Enter 不发送；compositionend 后根据真实按键意图处理，覆盖中文候选确认、Shift+Enter、Ctrl/Meta+Enter、长按和重复事件。未接收不能清空，已接收不重复投递。保留可访问的键盘导航，不让禁用按钮成为快捷键绕过点。

## 6. 文件、资源与版本

- 已确认选择为“保存后引用”或“使用已保存版本”。声明冻结版本时必须取得宿主可验证的内容身份；只有路径则显示 live path 语义。失败不会移除附件或输入。
- 内容身份基于实际字节；不静默变换换行、编码或正文。现有编辑器不支持的文件／过大文件显示限制，不能用截断文本替换原件。
- Prompt 恢复保留 Project/Personal、选择顺序和有意重复；发送前检查 changed/missing/revoked。历史快照保持原内容；不能把新编辑的片段自动当本次用户选择。
- 冲突比较包含本地、最新和必要基线；确认后的写入仍有 expected identity。用户选择“保留我的内容”不是永久无条件覆盖授权。
- 另存／删除恢复采用 create-only；正文与索引／mirror 不一致可诊断，并阻止依赖旧镜像的运行。
- retry/rewind/rollback 分别说明会话和文件影响；有脏稿先保证受保护副本。文件回退不回退授权、Stop、事件消费或根预算；失败不显示成功。
- 正式文件、待恢复稿、已确认运行 manifest 分开。运行中编辑不会静默换掉已批准蓝图／Prompt。

## 7. 结果、异常与资源闭环

共享只读投影从宿主记录派生 goal、state、reason、waiting_on、allowed_actions、source/session/task/run、evidence、usage。不可只用自由文本匹配生成可执行动作；需要宿主可核验原因码和目标 revision。

聊天的 todos/PlanBar 是会话内计划，ContinuationTask 是宿主持久任务，BlueprintRun 是一次实际执行。展示名称和关联必须区分；勾选待办不证明检查通过，也不自动生成持久任务或蓝图。独立 run 的源会话字段可为空。

| 动作 | 具体行为 |
|---|---|
| 查看结果 | 只读打开检查／差异／产物；历史引用不解析为当前同名文件。 |
| 带入当前会话 | 将用户选中的有来源结果引用加入当前草稿；零模型调用，仍需显式 Send；发送时再验证 scope 和会话状态。 |
| 合法自动续聊 | 使用已有 policy／绑定和消费规则，在原 session 新建至多一个 turn。 |
| 旧上下文重新绑定 | 准备当前目标、来源、版本、策略、预算的具体提案；保留旧消费和根账本，确认后由宿主判断。 |
| 预算／过期／撤权 | 打开原因与配置／新计划入口；不清零原链预算，不复活旧权限。 |
